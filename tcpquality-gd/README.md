# Low-volume Guangdong IPv4 TcpQuality comparison

This directory contains a narrowly scoped derivative of [ibsgss/TcpQuality](https://github.com/ibsgss/TcpQuality), based on upstream commit `6017af3fcb83b300b9a15b058d58062551d1c682`. The core retains the upstream license in `LICENSE` and adds a dedicated `--gd-proxy-only` mode.

## Exactly what it tests

- IPv4 return-path quality to Guangdong Telecom and China Mobile.
- IPv4 large-packet return-path quality to Guangdong Telecom and China Mobile.
- VPS-to-Guangdong single-thread **download only** for Telecom and China Mobile.
- The speed-test object is fixed to **64 MiB per carrier per run**, with curl's maximum-file-size guard. This is about 128 MiB downloaded per run / 256 MiB across baseline and after runs, excluding small dependencies/metadata, protocol overhead, unrelated VPS traffic, and possible provider accounting differences.

It does not test Unicom, any other province, IPv6, uploads, CERNET/education network, international connectivity, Apple CDN, or ranking/report upload. The script intentionally fails rather than silently falling back to a non-Guangdong speed-test node.

## Procedure

Run as root on a Linux VPS. The runner preflights `curl`, `ip`, `nstat`, `nping`, `traceroute`, `nexttrace-tiny`, and `awk`; it exits before testing if any are missing, so it will not download packages or silently omit the large-packet section. Install/check these dependencies before the baseline (package-install traffic is outside the test budget):

```sh
# Debian/Ubuntu: apt-get install -y curl iproute2 nmap traceroute
# Alpine: apk add curl iproute2 nmap-nping traceroute
# Install the official NextTrace Tiny binary separately; the executable must be named nexttrace-tiny.
command -v nexttrace-tiny
```

Then run the comparison as root:

```sh
/root/tq-gd.sh baseline
# Run ONLY tcpfit base tuning; do not run auto-tune or sweep.
tcpfit tune --role proxy --bw <known-bandwidth-Mbps>
/root/tq-gd.sh after
/root/tq-gd.sh compare
```

Obtain this runner from the user's repository:

```sh
curl -fsSL https://raw.githubusercontent.com/hytuytujyt/script/main/tcpquality-gd/run.sh -o /root/tq-gd.sh
chmod 700 /root/tq-gd.sh
```

Records are stored in `/root/tcpquality-gd-compare/` (override with `TCPQUALITY_GD_DATA_DIR`). Baseline/after each refuse a second run to prevent accidental additional traffic. Back up records before starting a fresh comparison; explicit reset is `RESET=YES /root/tq-gd.sh reset`.

## Data budget notes

The 64 MiB setting caps each successful single-thread download, not all network traffic generated by the VPS. The expected data payload is four downloads × 64 MiB = 256 MiB over the two runs. Route probes are small, but installing dependencies/core files, retransmissions, concurrent traffic, and provider billing rules are outside that payload calculation. The runner records the default-interface RX+TX counter delta during each pass; it includes unrelated traffic and is not a guarantee of provider-billed bytes.

`tcpfit tune --role proxy --bw N` applies local base TCP settings and does not run iperf throughput measurement when given a numeric bandwidth. Do not use `--bw auto`, `probe`, `sweep`, or the one-click workflow under this low-traffic budget.
